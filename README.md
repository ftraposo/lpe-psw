# PEPS·EC — Political Economy & Political Science Early Career Workshop

A Quarto project for the workshop site, jointly hosted by **LSE, UCL, and Cambridge**. Now in its **second edition**, with a "Past Edition" section covering the first workshop (30 January, LSE).

## Files & folders

- `index.qmd` — all page content (hero, about, themes, CFP, key dates, venue, **past edition**, organizers, footer), written as raw HTML inside a single fenced block. Quarto passes this through untouched.
- `style.css` — all styling. Colors, fonts, and spacing live as CSS variables at the top (`:root`).
- `_quarto.yml` — project config. `theme: none` disables Quarto's default Bootstrap styling so your custom CSS renders exactly as designed. `output-dir: docs` tells Quarto to build into `docs/`.
- `images/` — organizer photos and first-edition event photos/PDF, referenced from `index.qmd` as `images/<file>`.
  - `marta-antonetti.jpeg`, `elise-antoine.jpg`, `luis-cornago-bonal.jpeg`, `kun-heo.jpg`, `leo-falabella.png` — organizer photos
  - `edition1-photo1.jpg`, `edition1-photo2.jpg`, `edition1-photo3.jpg` — gallery photos from the first workshop
  - `first-edition-programme.pdf` — the original programme PDF, linked as a download in the Past Edition section
- `docs/` — **the rendered, ready-to-serve website.** This is what GitHub Pages actually serves. It's generated by `quarto render` — you shouldn't need to hand-edit anything inside it.

## ⚠️ If you're uploading via the GitHub website (not git)

This is the step that caused the last deploy to silently fail, so to be explicit:

1. **Unzip this file on your computer first.** GitHub does not unzip files for you — dropping the `.zip` itself into a repo will not produce a working site.
2. Open the **`docs/`** folder inside the unzipped project (`site/docs/`). This is the folder to upload — not the outer `site/` folder, and not `index.qmd`/`style.css` on their own (those are just the *source*, not what Pages serves).
3. In your GitHub repo, delete whatever is currently inside `docs/` first, so old files don't linger.
4. Drag in **the contents of `docs/`** (`index.html`, `style.css`, `search.json`, `sitemap.xml`, `robots.txt`, the `images/` folder, and the `site_libs/` folder) directly into the repo's `docs/` folder, so `docs/index.html` sits at that path — not `docs/docs/index.html`.
5. Commit to `main`. Check the **Actions** tab for a "pages build and deployment" run, then hard-refresh the live page (Ctrl/Cmd+Shift+R).

## Editing content

Every placeholder is wrapped in `[square brackets]` and highlighted in green. Open `index.qmd` and search for `placeholder` to find them:

- Date, venue, submission deadline (hero section)
- "Who this is for" paragraph (about section)
- Call for Papers copy and submission rules
- Key dates timeline (4 milestones)
- Venue address and travel info
- Organizer institutions/departments, plus 3 blank organizer slots reserved for incoming UCL/Cambridge committee members
- Contact email and social links
- Footer year

To add a new organizer photo: drop the image into `images/`, then in `index.qmd` find the relevant `.person-card` block in the Organizers section and either add `<img class="avatar-photo" src="images/your-file.jpg" alt="Name">` (replacing a placeholder `<div class="avatar">?</div>`) or swap an existing filename.

To update the Past Edition section for a future (third) edition, either edit it in place with the new programme, or duplicate the section and give the old one a distinct id (e.g. `#edition-1`, `#edition-2`) if you want to keep both visible.

## Working locally

1. [Install Quarto](https://quarto.org/docs/get-started/) (or `pip install quarto-cli`).
2. From the project folder, preview with live reload:
   ```bash
   quarto preview
   ```
3. Build the static site into `docs/`:
   ```bash
   quarto render
   ```
   Do this every time you edit `index.qmd`, `style.css`, or `_quarto.yml` — the `docs/` folder is what's actually deployed, and it will NOT update itself.

## Deploying to GitHub Pages

**Option A — serve the `docs/` folder (matches current setup)**

1. Repo: `github.com/<your-username>/lpe-psw` (or rename the repo if you'd like the URL to reflect the new branding).
2. Push the whole project, including the rendered `docs/` folder:
   ```bash
   git init
   git add .
   git commit -m "Second edition: LSE/UCL/Cambridge + past edition section"
   git branch -M main
   git remote add origin https://github.com/<your-username>/<repo-name>.git
   git push -u origin main
   ```
3. In the repository: **Settings → Pages** → Source: "Deploy from a branch" → Branch: **main**, folder: **/docs** → Save.
4. Every future update: edit `index.qmd`, run `quarto render`, commit the updated `docs/` folder, push.

**Option B — `quarto publish` (no manual render/commit step)**

```bash
quarto publish gh-pages
```
Renders and pushes straight to a `gh-pages` branch; point GitHub Pages at that branch instead of `docs/`. Re-run after every content change.

### Optional: custom domain

Add a `CNAME` file to the repo root (or `docs/`, if serving from there) containing just the domain name, and point your DNS at GitHub Pages.

## Design notes

- Fonts: Fraunces (display), Inter (body), IBM Plex Mono (dates/labels) — loaded from Google Fonts via CDN in `_quarto.yml`'s `include-in-header`.
- Colors and type live as CSS variables at the top of `style.css` (`:root`).
- `theme: none` in `_quarto.yml` keeps Quarto from injecting Bootstrap — don't remove it unless you want to redesign around Bootstrap instead.
- New CSS added for this edition: `.host-chip` (institution pills in the hero), `.edition-banner`, `.programme-list`, `.gallery-grid` (Past Edition section), and `.avatar-photo`/`.inst-tag` (organizer photos).
